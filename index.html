03 Process

From an idea to a zip, in five checks.

  1. 01

    Spec it

    A written behaviour first: what the command does, who may run it and what happens when it fails.

  2. 02

    Build it small

    One module at a time, wired through the same permission, cooldown and ownership checks as its neighbours.

  3. 03

    Static checks

    Compile every file and validate every slash option before a bot ever connects to Discord.

  4. 04

    Run the suites

    475 API checks and a 19-page browser sweep at four widths, with a clean console expected.

  5. 05

    Package honestly

    Zip only what passed. If a row fails, the release waits — the site changes the next day, not the claim.

05 Standards

How we ship.

These are not aspirations on a slide. Each one is a rule the code and the release process already follow.

01Plain Node.js
One runtime, discord.js and a folder of modules. No build step between an edit and a restart.
02Your data stays yours
State lives in JSON files on the host you chose. There is no Kernel cloud database in the middle.
03No telemetry
The bot does not phone home. What it records is what you can read in your own files.
04Tested before shipped
Compile check, 475 API checks, option checks and browser sweeps — the same suites every release.
05No invented numbers
When a feature cannot be verified, the site says so instead of printing a reassuring placeholder.
06Small surface
Every command has to earn its place. There is no fixed ceiling; the list grows only when a feature does, and it sits at 107.

06 Open seat

There is one seat open.

We are looking for someone who wants to own a slice of the bot — commands, automod or the economy pack — and keep the same standard: test it, document it, do not inflate it. No application form. A message with what you have built is enough.

Before you write.

Do I need to be in a specific Discord server?

No. The contact form and GitHub are enough to start a conversation. Being reachable on Discord helps later, once there is a change to review, but it is not a gate.

Is this a paid position?

No. Kernel has no paid tier, so there is no budget to pay contributors. What it offers is real ownership of a slice of the bot, public credit on this site, and code that ships.

What should I know already?

Node.js and discord.js basics for bot work — commands, events, permissions. The website is plain HTML, CSS and JavaScript with no framework, so a working knowledge of the browser is enough for site changes.

How is work checked?

Everything passes the same gate as a normal release: every file compiles, 475 API checks pass, the 13-check prefix adapter passes, slash options validate, and a 19-page browser sweep runs at four widths with a clean console. A change that fails a row does not ship.

Will I get a developer card?

Yes, once you are part of the build. Cards use real accounts and public records — the open seat stays visibly empty until then, because inventing a presence is not how this site works.
